# Лабораторная работа №2. Чтение информации из графических файлов

## Описание программы

Веб-приложение предназначено для получения информации о графических файлах форматов JPEG, GIF, TIFF, BMP, PNG и PCX.

Программа выводит следующую информацию:

- имя файла;
- формат изображения;
- ширину и высоту в пикселях;
- разрешение по горизонтали и вертикали (DPI);
- глубину цвета;
- тип сжатия;
- состояние файла.

При нажатии на строку таблицы можно получить дополнительную информацию о файле и посмотреть само изображение.

## Запуск программы

Веб-приложение доступно по ссылке:
[https://knvpmrdsn.github.io/pkg/lab2/](https://knvpmrdsn.github.io/pkg/lab2/).

Для локального запуска необходимо открыть файл `index.html` в браузере.

Файлы можно добавлять с помощью кнопок выбора файлов и папок,
а также перетаскиванием в соответствующую область сайта.

## Структура проекта

Программа разделена на три слоя:

### Presentation Layer — пользовательский интерфейс

- `ui/template.html` — разметка страницы.
- `ui/style.css` — оформление страницы.
- `ui/app.js` — взаимодействие с пользователем, вывод результатов, сортировка, фильтрация и переключение страниц таблицы.

### Core / Business Logic Layer — логика программы

- `engine/scan.js` — распределение файлов между рабочими потоками, управление процессом сканирования.
- `engine/worker.js` — обработка отдельного файла и передача результатов в основной поток.

### Data / Parsing Layer — обработка данных

- `parsers/metadata.js` — определение формата файла по его сигнатуре и побайтовое чтение характеристик изображения.

### Дополнительные файлы и папки

- `tests/` — наборы графических файлов для тестирования программы.
- `build.py` — скрипт для объединения исходных файлов.
- `index.html` — готовая версия веб-приложения.
- `README.md` — описание программы и документация.

Для пересборки программы используется команда `python build.py`.

## Используемые средства

Программа написана с использованием HTML, CSS и JavaScript.

Сторонние библиотеки для получения информации об изображениях не используются. Все необходимые данные считываются непосредственно из содержимого файлов.

Для чтения данных используются:

- `File.slice()` — получение определенного участка файла;
- `ArrayBuffer` — хранение считанных байтов;
- `DataView` — чтение числовых значений из массива байтов;
- `Web Workers` — многопоточная обработка файлов.

Для отображения изображений используются встроенные возможности браузера.

## Получение информации из графических файлов

### BMP

Информация считывается из структур BITMAPFILEHEADER и DIB-заголовка.

Из заголовка получаются размеры изображения, глубина цвета, тип сжатия и разрешение.

Разрешение хранится в пикселях на метр. Для перевода в DPI значение умножается на 0,0254.

Тип сжатия определяется по соответствующему числовому коду, например BI_RGB, BI_RLE8, BI_RLE4 или BI_BITFIELDS.

В индексированных изображениях используется палитра, в которой хранятся значения цветов, а пиксели содержат их индексы.

### JPEG

Информация получается путем поиска специальных маркеров внутри файла.

Из сегмента SOF считываются ширина, высота, количество цветовых компонентов и количество бит на компонент.

Глубина цвета вычисляется как произведение количества компонентов на количество бит на компонент.

Разрешение определяется по данным JFIF или Exif. Для проверки окончания файла используется маркер EOI (FF D9).

### PNG

Основная информация считывается из чанка IHDR, который содержит ширину, высоту, битность канала, тип цвета и метод фильтрации.

Глубина цвета вычисляется с учетом количества каналов. Для индексированных изображений используется битность индекса.

Разрешение считывается из чанка pHYs, если в нем задана физическая плотность пикселей.

В PNG используется сжатие Deflate. Для проверки окончания файла выполняется поиск чанка IEND.

### GIF

Размеры изображения считываются из Logical Screen Descriptor.

Глубина определяется по полю размера глобальной таблицы цветов. Для сжатия используется алгоритм LZW.

Информация о DPI в данном формате не предусмотрена.

Для проверки окончания файла используется байт 3B.

### TIFF

Информация хранится в специальном каталоге IFD (Image File Directory), состоящем из тегов.

Используются следующие основные теги:

| Номер тега | Назначение |
|---|---|
| 256 | Ширина изображения |
| 257 | Высота изображения |
| 258 | Количество бит на компонент |
| 259 | Тип сжатия |
| 277 | Количество компонентов |
| 282 | Горизонтальное разрешение |
| 283 | Вертикальное разрешение |
| 296 | Единица измерения разрешения |

В зависимости от размера значения оно считывается непосредственно из записи тега или по указанному в ней смещению.

Учитывается порядок следования байтов (Little Endian или Big Endian).

### PCX

Основная информация находится в заголовке размером 128 байт.

Размеры изображения вычисляются по координатам его границ. Глубина цвета определяется произведением количества бит на плоскость и количества цветовых плоскостей.

Разрешение по горизонтали и вертикали считывается непосредственно из заголовка.

Тип сжатия определяется по полю Encoding.

## Оптимизация быстродействия

Для ускорения работы используется ленивое чтение файлов. Программа не загружает изображение целиком, а считывает только необходимые участки файла.

Обработка выполняется в нескольких потоках с помощью Web Workers. Количество рабочих потоков зависит от характеристик компьютера, но не превышает восьми.

Это позволяет обрабатывать большое количество файлов без длительной блокировки пользовательского интерфейса.

Во время работы отображаются количество обработанных файлов, количество ошибок, общий размер файлов и процент выполнения. Сканирование можно приостановить и продолжить.

Для уменьшения нагрузки на интерфейс результаты разделены на страницы по 100 файлов.

## Проверка файлов

Формат изображения определяется по его содержимому, а не по расширению.

При обработке проверяются сигнатуры, размеры заголовков, смещения и конечные маркеры файлов. При обнаружении ошибки программа выводит соответствующий статус и продолжает обработку остальных файлов.

Проверка является структурной. Полное декодирование графических данных не выполняется, поэтому некоторые повреждения внутри данных изображения могут остаться необнаруженными.

## Тестирование

### Условия тестирования

Тестирование проводилось на ноутбуке со следующими характеристиками:

- Модель: ASUS ROG Strix G614JU.
- Процессор: Intel Core i5-13450HX.
- Оперативная память: 16 ГБ.
- Операционная система: Windows.
- Браузер: Google Chrome.
- Количество рабочих потоков: 8.

Время обработки файлов измеряется с помощью метода
`performance.now()` и отображается в секундах.
Время предварительного обхода папок и время нахождения
на паузе не учитываются.

### Порядок тестирования

1. Открыть файл `index.html` в браузере.
2. Выбрать необходимую папку из каталога `tests/` или перетащить ее в область загрузки.
3. Дождаться окончания обработки файлов.
4. Проверить количество обработанных файлов, количество ошибок и время выполнения.
5. Проверить корректность отображаемых характеристик изображений.
6. Проверить работу сортировки, поиска, фильтрации и переключения страниц.
7. Во время обработки большого количества файлов проверить возможность приостановки и продолжения сканирования.

### Проверка поврежденных файлов

Для проверки обнаружения повреждений были подготовлены файлы с нарушенной структурой:

- JPEG — отсутствует конечный маркер EOI;
- PNG — отсутствует чанк IEND;
- GIF — отсутствует завершающий байт;
- TIFF — повреждены данные каталога IFD;
- BMP — отсутствует часть графических данных;
- PCX — отсутствуют графические данные после заголовка.

При обработке смешанного набора ожидается обнаружение 1000 поврежденных файлов.

### Проверка быстродействия

Для оценки быстродействия используются наборы с различным количеством файлов и различным общим объемом.

Так как программа считывает только необходимые участки файлов, время обработки зависит преимущественно от количества файлов и сложности их структуры, а не от общего объема папки.

Поэтому обработка 600 JPEG-файлов общим объемом около 2 ГБ может выполняться быстрее, чем обработка 100 000 файлов значительно меньшего суммарного объема.

Время выполнения зависит от характеристик компьютера, скорости накопителя и используемого браузера.

## Ограничения

- Для TIFF анализируется первая IFD. Формат BigTIFF не поддерживается.
- Локальные палитры отдельных кадров GIF не анализируются.
- Контрольные суммы CRC в PNG не проверяются.
- Полная проверка RLE-данных PCX не выполняется.
- Возможность просмотра изображения зависит от поддержки его формата браузером.
- Если разрешение не указано в файле, выводится значение «Не задано».
